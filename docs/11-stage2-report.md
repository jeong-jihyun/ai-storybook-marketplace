# 2단계(판매) 개발 결과 — 2026-11-20

설계서 10장 2단계: 인증, 주문, 결제 연동, 서버 검증, 구매 권한 / 완료 기준: 테스트 구매 후 내 서재에 도서 등록, 중복 결제 방지

## 만든 것
| 구분 | 내용 |
|---|---|
| 회원 (MEM-001~005) | 보호자 가입(만 19세 이상 확인·약관), 로그인, 토큰 자동 갱신, 로그아웃(모든 기기), 정보 수정, 탈퇴 |
| 보호자 확인 (MEM-004) | PIN 4자리, 5번 틀리면 5분 잠금, 확인 후 10분 동안 유효 — 주문·결제·정보 변경·탈퇴에 필요 |
| 주문 (PAY-001) | 가격은 서버 판매가로 계산, 같은 버튼 두 번 눌러도 주문 1건(멱등성 키), 이미 산 책은 주문 거절 |
| 결제 검증 (PAY-003·007) | 영수증을 서버가 검증 → 결제 확정 → 구매 권한, 같은 영수증 재사용·남의 영수증·위조 영수증 거절 |
| 결제 방식 | 테스트 결제(돈 안 나감) 사용 중 / 구글 플레이·애플 검증 코드 준비(키 넣으면 켜짐) |
| 구매 권한 (PAY-004) | 산 사람만 전체 페이지, 내 서재, 상세 화면 '구매함' 표시 |
| 구매 복구 (PAY-008) | 스토어 영수증 다시 검증해 서재와 맞춤 (스토어 연결 후 화면에서 사용) |
| 주문 내역 (PAY-005) | 결제 완료·취소·실패 상태 표시 |
| 앱 화면 | 로그인, 회원가입, 보호자 PIN 패드, 주문 확인, 테스트 결제창, 결제 결과, 끝까지 읽기, 내 서재, 주문 내역, 계정 관리 |
| DB | Supabase 무료(서울) — 마이그레이션 002(판매), 003(외부 접근 잠금) |

## 검증
- 서버 테스트 67개 통과: 1단계 26 + 판매 36 (메모리·PostgreSQL 같은 시나리오) + 구글·애플 검증 5 (가짜 스토어 응답)
- 폰 크기 화면으로 실제 흐름 자동 확인: 비로그인 구매 → 로그인 안내 → 가입(입력 오류 표시) → PIN 틀림/맞음 → 테스트 결제 → 결과 → 8쪽 읽기 → 내 서재 → 다른 책 결제 취소 → 주문 내역 → 로그아웃 → 로그아웃 상태 읽기 차단
- Supabase: 테이블·책 10권·페이지 80장 입력, 모든 테이블 외부 접근 잠금(RLS) 확인

- 환불 요청(PAY-006, P1), 스토어 알림 웹훅: 실제 스토어 연결 때
- 이어 읽기·글자 크기·찜: 3단계
